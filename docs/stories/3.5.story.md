# Story 3.5: Pièces jointes privées

## Status

Done

## Story

**En tant qu'** utilisateur,
**je veux** joindre une preuve sans qu'elle devienne accessible à qui possède son adresse,
**afin qu'** un justificatif ne circule pas hors de l'application.

## Acceptance Criteria

1. Les fichiers sont stockés dans `storage/app/private`, **hors de la racine web** ; ⛔ un test vérifie qu'aucune URL publique ne les atteint.
2. La lecture passe par un contrôleur qui **contrôle l'autorisation avant de servir**, avec `X-Sendfile` (DEC-13) pour ne pas faire transiter le fichier par PHP.
3. Types et taille maximale sont **paramétrables** (3.4) ; un téléversement non conforme est refusé **côté serveur**, même si le contrôle client est contourné ; testé en forgeant la requête.
4. Le message de refus est explicite : « Ce fichier fait 8 Mo, la limite est de 5 Mo. Choisissez un fichier plus léger. » — la limite affichée est celle réellement paramétrée.
5. Le type réel du fichier est vérifié, pas seulement son extension ; un exécutable renommé en `.pdf` est refusé.
6. Les images sont redimensionnées côté serveur en vignette pour l'affichage en liste (poids en 3G, UX § 11.2).
7. Toute pièce jointe est rattachée à un objet et hérite de ses règles de visibilité ; l'accès à la pièce d'un objet non autorisé est refusé.
8. Le téléversement affiche une progression et reste utilisable depuis l'appareil photo d'un téléphone.

### Stockage et non-accessibilité (AC 1)

Disque `private` **hors racine web**. Protection en **deux barrières** : le chemin hors `public/`
**et** un `Require all denied` explicite Apache sur `/storage` (DEC-13) — « la protection ne repose
pas seulement sur le fait que le chemin est en dehors de `public/` ». Chemin
`private/{module}/{annee}/{mois}/{ulid}.{ext}`, **nom d'origine en base uniquement**. [Source: architecture/11-pices-jointes-prives.md#111-stockage-a-04-nfr15]

### Deux modes de lecture (AC 2, 6)

| Mode | Usage | Mécanisme |
|---|---|---|
| **Contrôlé** | Le fichier lui-même | Route → Policy de l'attachable → `X-Sendfile` (Apache sert après validation PHP) |
| **Signé** | Vignettes en liste | URL signée Laravel, validité **10 min** |

`X-Sendfile` : `BinaryFileResponse::trustXSendfileTypeHeader()` active le mécanisme **sans changer le
contrôleur** ; hors Apache (local/CI), Symfony sert le fichier en flux. On garde le contrôle
applicatif **et** l'efficacité serveur. [Source: architecture/11-pices-jointes-prives.md#112-contrle-daccs-la-lecture]

### Validation infalsifiable au téléversement (AC 3, 4, 5)

Refus **côté serveur**, indépendant du client :
1. Type MIME **par le contenu** (`finfo`), jamais extension ni en-tête client.
2. Liste blanche + taille max **lues dans les paramètres** (3.4), modifiables sans code.
3. Extension réécrite depuis le MIME validé.
4. Images ré-encodées (EXIF supprimé, charge neutralisée) ; **HEIC → JPEG**.
5. Vignette **en file d'attente** ; aucune pleine résolution en liste.

Le message de refus (AC 4) porte la **limite réellement paramétrée**, pas une constante — un test
modifie le paramètre 3.4 et vérifie que le message change. [Source: architecture/11-pices-jointes-prives.md#113-validation-au-tlversement-nfr16-q11]

### Héritage de visibilité (AC 7) — le cœur mécanique

`attachments` est **polymorphe** (`attachable`). La lecture n'a pas de règle de visibilité propre :
elle **délègue** à la policy de l'objet attaché (`Gate::authorize('view', $attachable)`). Une pièce
d'un objet non autorisé est refusée. En 3.5, l'attachable de démonstration est la `Person` (fiche
3.2) ; les consommateurs réels arrivent : documents du dossier personnel (**3.6**), justificatifs
financiers (**epic 4/8**). C'est un story **mécanisme**, comme 3.4 pour les paramètres. [Source: architecture/11-pices-jointes-prives.md#112, app/Policies/Identity/PersonPolicy.php]

### Autorisation et campagne (AC 2, 7)

La visibilité effective est **objet-dépendante**, mais SOC-01 exige que chaque route protégée soit
déclarée dans la matrice (role × route). Comme `people.show` (permission large + object-scoping en
policy), introduire `piece_jointe.consulter` / `piece_jointe.creer` pour les cinq rôles métier ;
l'AC 7 (scoping par objet) est portée par la policy de l'attachable et testée séparément. La vignette
signée n'est **pas** une route à rôle (protégée par signature). ⛔ **À valider PO** : noms de
permissions et articulation matrice/policy pour un objet polymorphe. [Source: config/authorization-matrix.php, prd/socle-transverse.md#SOC-01]
